# Guided Project setup

Project registration and settings use a guided, host-scoped flow. Reuse the owner's
confirmed public HTTP API with temporary state/owned repositories, real browser
journeys, and disposable public CLI fixtures.

- Select a registered host and pick a folder through DirectoryBrowser. The path
  control is read-only, with an inline folder icon; clicking it opens the picker.
- Discover the repository name, installed agents, native permission choices,
  package-manager/check scripts, existing guidance and GitHub remote/account hints.
  Discovery reads configuration; it never runs repository scripts or switches a
  global GitHub login.
- Use provider-specific permission choices, detected check selections and a Matt
  Pocock workflow default. Basic settings save independently of unavailable
  execution prerequisites. Missing prerequisites explain how to complete setup.
- Reuse existing repository guidance. Offer a bounded Matt Pocock setup Assignment
  for tracker/layout, domain-modeling and writing-for-agents; preserve existing
  documents and retain the workflow's owner questions and review gates.
- Inventory/import existing GitHub CLI logins explicitly, privately and on their
  owning host. Show created profiles and their sign-in state rather than hiding
  unavailable ones. Reuse configured Project bindings and GitHub policy.
- Use native Herdr status markers on chats/workers, and its status rollup on folded
  Project summaries. Offline status remains unknown, and archived work is excluded.

Advanced legacy settings remain stored. Ordinary users do not edit command-array
JSON, environment JSON, permissions prose, or shared-path lists in the setup flow.

## Using the setup flow

Open **Projects → Set up a Project** and select the registered host. Click the folder
box or its inline icon, then choose **Use this folder** in the existing browser.
The next steps offer the installed agents, their native permission modes, detected
repository checks, and saved GitHub logins. Codex **Approve for me** uses native
automatic approval review inside its workspace sandbox; reviewers retain read-only
access. A planning target guides handoffs rather than promising a hard token cap.

Choose **Create a guided repository setup Assignment** when domain language or
coding standards need work. Existing Projects offer the same action under their
general settings. The Assignment uses the pinned setup/domain-modeling and
writing-for-agents workflow, retains actual owner questions, proposes changes in an
owned worktree and preserves existing documents. It starts through the existing
native workflow controls; registering a Project does not launch a paid agent.

GitHub settings detect the remote from the verified checkout and reuse existing
Project policy and account choices. Pending accounts remain visible with their
sign-in state. GitHub integration currently uses the connection server's verified
account; execution-Machine account selectors keep their own scope. Select a saved
login to import it privately without switching the native active account. An SSH
alias can identify the GitHub remote, while dynamic SSH or shell routing requires
explicit selection. Existing SSH files and global configuration remain untouched.

Repository metadata supplies available reviewers and branch check names for the
advanced automation choices. Issue import works with basic settings; automatic
merge and branch updates keep the existing strict policy and fresh-evidence gates.
